Stuck trades

Every Karum listing that is not in a terminal state, worst first. selling and reconciling are transient and resolve themselves; one sitting there for hours is a bug. paid_undelivered is the only state that can need a human, and it never means money was lost.

Every button here goes through the same writer the portal uses. Nothing on this page touches the database directly, and every leg is idempotent on its original correlation id, so pressing twice is safe and pressing after something already succeeded is a no-op replay. Never resolve one of these with hand-written SQL: that is the exact thing this page exists to make unnecessary.

Refund is deliberately separate from force-return. They are not always both correct: a return with no refund is right when the buyer never paid, and a refund with no return is right when the goods already reached them.
